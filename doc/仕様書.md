## 1. ゲーム概要

| 項目 | 内容 |
|------|------|
| ゲーム名 | こじらせ大劇場（キャッチコピー：〜大根役者選手権〜） |
| 種別 | 即興演劇ゲーム（Webアプリケーション） |
| プレイ人数 | 1〜10人（2〜8人推奨。1人は一人芝居モード。1台に複数人可） |

| プレイ時間 | 1セッション 5〜10分程度 |

## 3. 進行フロー

```
① ホストがルーム作成
      → ルームコードが発行される

② 参加者がルームコードで入室・名前入力
      → ホスト画面に参加者一覧が表示される

②' 1台で複数人プレイする場合
      → ロビーの「＋この端末にプレイヤーを追加」で人数分の名前を入れる
      → 携帯回し（全員が1台）とオンライン混在（1台に数人＋別端末）の
        どちらも同じ操作で成立する（モード切り替えは無い）
      → 録音は1台のマイクで1発どり。AIが台本と照合して発話を各人に帰属させる
      → 詳細: docs/superpowers/specs/2026-08-25-local-multiplayer-design.md

③ ホストがジャンル選択
      → AIが参加人数分の役割・台本を生成

④ 各プレイヤーに役が自動配役
      → 自分の役・セリフが表示される

⑤ ホストがゲーム開始ボタン
      → 全員に準備フェーズ開始が通知される

⑥ 準備時間（自分のペースで台本を読む）
      → 「準備完了」ボタンを押すと待機
      → 全員が準備完了 or ホストが強制スキップで次へ

⑦ 録音（同時・ワンテイクのみ）
      → ホストが「録音開始」ボタン → サーバーがSocket.ioで全員に同時broadcast → 全員録音開始
      → ホストが「録音終了」ボタン or 最大5分でサーバーが自動終了
      → 全員の録音を停止・サーバーに送信
      → ロビーで「声の配信」がONなら、録音中は離れた端末どうしの声もWebRTCで
        聞こえる（ベストエフォート。繋がらない相手がいても録音・採点は無傷）
      → 詳細: docs/superpowers/specs/2026-08-26-live-audio-design.md

⑧ AI評価
      → 音声 → 文字起こし（Whisper API）
      → Claude API が台本と文字起こしを照合して採点・コメント生成

⑨ 結果表示
      → 全プレイヤーのスコアを一覧表示

⑩ SNSシェア
      → スコアカード画像を生成してシェア（X・LINE等）
```

## 4. 評価基準

| 評価項目 | 内容 | 形式 |
|----------|------|------|
| 演技力 | 台本の内容を正確に・豊かに表現できているか | ☆1〜5 |
| 感情 | 声・テキストから感情の豊かさを判定 | ☆1〜5 |
| こじらせ度 | 役・台本への感情移入度・面白さの度合い | ☆1〜5 |
| AIコメント | 演技全体への総評テキスト | テキスト |

## 6. AI機能詳細

### 6-1. 台本生成（Claude API）

- 入力：ジャンル・プレイヤー人数
- 出力：世界観説明・各プレイヤーの役名・キャラクター説明・セリフ（1分30秒〜2分相当）
- カオスモード時は設定・役割・世界観を意図的に破綻させた内容を生成

### 6-2. 音声処理

| 処理 | 方法 |
|------|------|
| 文字起こし | Whisper API（OpenAI） |
| 声量メーター | Web Audio API（AnalyserNode）+ Socket.io |

#### 声量メーターの仕様

- 各クライアントがマイク入力を Web Audio API の `AnalyserNode` で解析し、音量レベル（0〜1）を取得
- 取得した音量レベルを Socket.io で定期的にサーバーへ送信（100ms ごと）
- サーバーは全プレイヤーの音量レベルをまとめて全員にブロードキャスト
- 録音画面の声量メーターは全員分の音量を合成・平均して表示する

### 6-3. 評価（Claude API）

- 入力：台本テキスト・文字起こしテキスト
- 出力：演技力☆・感情☆・こじらせ度☆・AIコメントテキスト

## 9. 公開ガード

URLを配って運用するための歯止め。詳細は `docs/superpowers/specs/2026-08-13-public-guard-slice-b-design.md`。

| 環境変数 | 既定 | 効果 |
|---|---|---|
| `DAILY_GAME_LIMIT` | 5 | 1日にAIを使えるゲーム数 |
| `AI_ENABLED` | true | false で全ゲームを簡易モードに |
| `PUBLIC_ENABLED` | true | false で新規ルーム作成を拒否 |

- 枠の判定は `start_game` の入口で1回だけ行い、そのゲームは最後まで同じモードで進む（1ゲーム＝1消費・中断しても返さない）。
- 枠を使い切ったゲームは `plays/` の手書き台本＋スタブ採点で進む。AI は一切呼ばない。
- 手書き台本は `plays/<ジャンル>/*.json` に置く（1ファイル1台本）。**ディレクトリ名がジャンルの正**で、JSON の `genre` が食い違う台本は置き間違いとして読み込まれない。直下に置いたファイルは読み込まれず、起動ログに警告が出る。
- `ANTHROPIC_API_KEY` 未設定（＝設定ミス）でも手書き台本に落ちる。開発用スタブ台本は実プレイヤーには出さない。
- 簡易モードであることは、ロビー（開始前の見込み）と配役・結果画面（`script_ready` の `aiMode` ＝その回の確定値）に一文で表示する。
- レート制限は `create_room` が同一IP 60秒に5回、`POST /upload` が同一IP 60秒に30回。
- ログ：`start_game` ごとに `aiMode` と当日の消費数（`used/limit`）、レート制限で断ったときは導出IP。`create_room` は生の `x-forwarded-for` も併記する（プロキシ段数の想定が正しいかを本番で照合するため）。
- カウンタはメモリ上のみ。再デプロイ・再起動でリセットされる。
