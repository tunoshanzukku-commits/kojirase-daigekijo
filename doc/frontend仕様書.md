## 2. 状態管理

### GameContext

画面間で共有するグローバル状態。`App.tsx` の `useState` で管理し、`NavigateFn` 経由で更新する。

```typescript
interface GameContext {
  playerName: string      // プレイヤー名
  isHost: boolean         // ホストかどうか
  roomCode: string        // ルームコード（4文字）
  genre: string           // 選択ジャンルID
  fromResult?: boolean    // 結果画面からロビーに戻ったか
  script: ScriptData | null   // AI生成台本（Socket.io統合時にRoomSnapshotから反映）
  scores: PlayerScore[]       // AI評価結果（同上）
}
```

`script` / `scores` は Socket.io 統合時にサーバーの `RoomSnapshot` を受け取る器。現在のモックでは未使用（各画面はハードコードのモックデータを使用）。

### 画面遷移

```typescript
type Screen = 'top' | 'lobby' | 'casting' | 'prepare' | 'recording' | 'evaluating' | 'result'
type NavigateFn = (screen: Screen, updates?: Partial<GameContext>) => void
```

遷移フロー：

```
top → lobby → casting → prepare → recording → evaluating → result → lobby
```

### ジャンル別背景グラデーション

ジャンル選択時に背景がリアルタイムでプレビューされる（`transition-colors duration-700`）。

| ジャンルID | グラデーション |
|-----------|--------------|
| romance | pink-300 → rose-200 → fuchsia-300 |
| horror | red-300 → gray-300 → red-400 |
| comedy | yellow-300 → lime-200 → green-300 |
| jidai | amber-300 → orange-200 → yellow-300 |
| sf | indigo-300 → blue-200 → cyan-300 |
| mystery | gray-400 → slate-300 → zinc-400 |
| emotion | purple-300 → violet-200 → indigo-300 |
| chaos | fuchsia-300 → cyan-200 → yellow-300 |
| （未選択） | sky-200 → blue-100 → sky-200 |

### プレイヤー色と端末グループ表示（1台に複数プレイヤー）

1台に複数人が乗る場合、部屋全体の参加順で 1P〜10P の固定色（朱・群青・深緑…）を割り当て、ロビーの㊞・配役カード・台本の罫とバッジ・結果一覧の㊞で**同じ人が常に同じ色**になるようにしている。ロビーの参加者一覧は人単位の「あなた」表示ではなく、**端末ごとのグループ表示**（「この端末」／「オンライン」）に変わる。台本は局所（この端末）のプレイヤーの台詞だけを色分け・名前バッジ付きにし、遠隔（他端末）は罫の太さだけで区別する。色の定義とコントラスト実測値、グループ表示の詳細ルールは設計書を参照。

→ `docs/superpowers/specs/2026-08-25-local-multiplayer-design.md`（5章・6章・7章）

## 4. 画面仕様

### 4-1. トップ画面（TopScreen）

**状態：** `mode: 'select' | 'create' | 'join'`

| モード | 内容 |
|--------|------|
| select | 「ルームを作る」「ルームに参加する」ボタン |
| create | 名前入力 → 作成ボタン（`isHost: true`、ランダム4文字コード発行） |
| join | 名前入力 + ルームコード入力（4文字） → 参加ボタン（`isHost: false`） |

**入力制限：**
- 名前：最大10文字（`maxLength`）。送信時に trim し、空なら送信不可
- ルームコード：大文字A〜Z以外を自動除去し4文字に制限（入力時に正規化）
- ※フロントの制限は補助。確定的な検証はサーバー側で行う（backend仕様書「入力検証」参照）

---

### 4-2. ロビー画面（LobbyScreen）

**表示内容：**
- ルームコード（大文字・トラッキング広め）
- 参加者一覧（ホストバッジ・「あなた」表示）
- ジャンル選択グリッド（ホストのみ操作可）
- ゲーム開始ボタン / 解散・退出ボタン

**ジャンル選択：**
- タップ即時にコンテキスト更新 → 背景色がリアルタイムプレビュー
- 選択済みは紫背景でハイライト

**解散・退出：**
- 2段階確認（確認ダイアログ表示 → 実行）
- 実行時に GameContext をリセットしてトップ画面へ

**結果画面から戻った場合（`fromResult: true`）：**
- 参加者ごとに帰還状況バッジを表示
  - `✓ ロビー待機中`（emerald）：ロビーに戻っている
  - `結果確認中...`（slate）：まだ結果画面にいる
- 初回ロビー参加時は表示しない

**台本生成中オーバーレイ：**
- ホストが「ゲームを開始する」を押すと、ロビーの上に半透明オーバーレイ（✍️🤖「AIが台本を執筆中...」＋選択ジャンル名＋スピナー）を全員に表示
- `script_ready` 受信で配役画面へ遷移（モックでは2.5秒後に遷移）
- 生成失敗時はオーバーレイを閉じ、トーストでエラーを表示してロビーに留まる

**ゲスト向けデモ：** 「（デモ）次の画面へ →」ボタン（点線ボーダー）

---

### 4-3. 配役画面（CastingScreen）

**表示内容：**
- 世界観テキスト
- 自分の役名・キャラクター説明・セリフ一覧（紫カード）
- 他プレイヤーの役名一覧
- 「台本を読む →」ボタン → PrepareScreen

---

### 4-4. 準備画面（PrepareScreen）

**表示内容：**
- 全員分の台本（自分のセリフは紫ハイライト、他は sky-blue）
  - ト書き：`🎭` + イタリック
  - セリフ：`「」` で括る
- 準備状況パネル（全員の準備完了状況）
- 準備完了トグルボタン
- ホスト用：録音開始ボタン（円形タイマー付き）

**準備完了トグル（全員共通）：**
- 未完了：緑ボタン「準備完了！」
- 完了：emerald 枠ボタン「✓ 準備完了（タップで取り消し）」、ホバーで赤みがかって取り消しを示唆

**ホスト録音開始ボタン：**

| 状態 | タイマー | ボタン |
|------|---------|--------|
| 待機中（タイマー進行） | 紫でカウントダウン | グレー・押せない |
| 全員準備完了 | 即✓（紫） | 紫「全員準備完了！録音開始 🎬」 |
| タイマー切れ（未全員） | ✓（アンバー） | アンバー「スキップして開始」 |

- タイマー上限：`SKIP_UNLOCK_SEC = 30`（秒）
- ゲストが準備を取り消すと `allReady` が即座に `false` になりボタンが無効化

**マイク許可フロー：**
- 画面表示時に `navigator.mediaDevices.getUserMedia({ audio: true })` を実行（許可確認後ストリームは即停止）
- 状態：`pending`（🎤 マイクを確認中...）/ `granted`（🎤 マイクOKバッジ・emerald）/ `denied`（赤の案内カード＋「マイク許可を再試行」ボタン）
- `granted` 以外の間は準備完了ボタンを無効化（マイクOKが準備完了の前提条件）

**ゲスト向けデモ：** 「（デモ）次の画面へ →」ボタン

---

### 4-5. 録音画面（RecordingScreen）

**フェーズ：**

#### フェーズ1：カウントダウン

- 3・2・1 と大きく表示（`fadeScale` アニメーション）
- 0 になると「START!」（emerald）を約0.8秒表示し、録音フェーズへ移行

#### フェーズ2：録音中

**Sticky ヘッダー（`top-0`）：**
- REC インジケーター（赤点滅）+ 経過時間 + プログレスバー
- 最大録音時間：`MAX_SEC = 300`（5分）、超過時に自動終了

**台本表示：**
- 全員分のセリフをスクロール可能なカードで表示
- 自分のセリフ：紫ハイライト・太字・`「」`・ト書きは `💡` + 小文字
- 他のセリフ：sky-blue・通常ウェイト

**操作ボタン：**
- ホスト：「録音終了」ボタン（赤）→ EvaluatingScreen
- ゲスト：「ホストが終了を押すまで演じ続けてください」 + デモ用スキップボタン

**固定下部バー：**

左半分：絵文字スタンプボタン（5種）
- `👏 😂 🔥 😍 💪`
- タップで浮き上がる絵文字アニメーション（`floatUp` 2.2秒）
- 他プレイヤーからの自動リアクション（4〜12秒ごとのモック）

右半分：声量メーター
- 12本のバー、100ms ごとに更新
- 青（低）・アンバー（中）・赤（高）で色分け
- ※現在はランダムモック。実装時は Web Audio API + Socket.io で全員分を合成

**BGM/効果音パネル：**

画面右端の「音」タブで開閉するスライドパネル（誰でも操作可）。

| 種別 | 内容 |
|------|------|
| BGM（4種） | ドラマチック🎻 / 不気味👻 / コミカル🎵 / バトル⚔️。単一選択、再タップ or 🔇で停止 |
| 効果音（6種） | ドラムロール🥁 / どーん💥 / ファンファーレ🎉 / 悲鳴😱 / 笑い声🤣 / チーン🔔。タップで単発再生（押下フラッシュ演出） |

- backend の `send_bgm` / `send_sfx` / `bgm_changed` / `sfx_played` イベントに対応
- 実音声の再生は未実装（現在はUI演出のみ）

**声の配信（ライブ音声。ロビーでON時のみ）：**

離れた端末の声を WebRTC で受け取ったら `<audio>` 要素で再生する（Web Audio 経由で鳴らすとブラウザのエコーキャンセラの参照から外れ AEC が効かなくなるため）。同時に `audioBus.connectRemote()` で `mixDest`（鑑賞用トラックの合成先）へも分岐し、結果画面で聞ける「みんなの熱演」に相手の声を含める。マイクは録音開始まで取得せず、準備フェーズで先に張った接続に対して録音開始時に `sender.replaceTrack()` で差し込む（SDPの再交渉を要さないため即座に音が通り、マイクは本当に録音中しか動かない）。配線・トラップの詳細は `docs/superpowers/specs/2026-08-26-live-audio-design.md`（5章）を参照。

### 4-6. AI評価中画面（EvaluatingScreen）

自動進行するステップリスト（操作不要）。

| ステップ | 表示テキスト | 待機時間 |
|---------|------------|--------|
| 1 | 音声を受信中... | 1200ms |
| 2 | 文字起こし処理中（Whisper API）... | 1200ms |
| 3 | AIが台本と照合中... | 1200ms |
| 4 | スコアを計算中... | 1200ms |
| 5 | 総評コメントを生成中... | 1500ms |

全ステップ完了後、自動で ResultScreen へ遷移。

### 4-7. 結果画面（ResultScreen）

**表示内容：**
- 🥇 最優秀俳優賞バナー（合計スコア1位）
- 全プレイヤーのスコアカード（合計点降順）
  - メダル（🥇🥈🥉）・合計点
  - 演技力 / 感情 / こじらせ度（☆1〜5）
  - AI総評コメント
  - 自分のカードは紫ハイライト

**アクション：**
- 「結果をシェアする 🔗」（未実装）
- 「ロビーへ戻る」→ `onNavigate('lobby', { fromResult: true })`

## 5. エラー表示

| 種別 | 表示方法 |
|------|---------|
| トップ画面の入室失敗（ルームが見つからない・ゲーム進行中） | フォーム直下に赤文字でインライン表示 |
| ゲーム中の非同期エラー（台本生成失敗・評価失敗等） | 画面上部の共通トースト（`components/Toast.tsx`、4秒で自動消滅、タップで閉じる） |

## 6. 切断時のUI

| ケース | UI |
|--------|-----|
| ホスト切断（`room_dissolved`） | モーダル「ホストが退出したためルームが解散されました」→ OKでトップへ |
| ゲスト切断（`player_left`） | トースト「〇〇が退出しました」＋参加者一覧から削除。ゲームは続行 |
| 切断者の結果表示 | ランキング最下位にグレーの退出カード「🚪 途中退出のため評価なし」（星・コメント非表示） |

※モック実装は見送り（Socket.io統合時に実装）。

## 7. モックデータ

| ファイル | 内容 |
|---------|------|
| `mockScript.ts` | 時代劇17エントリの台本（player / character / action? / line）、世界観 `MOCK_WORLD`、ロール情報 `MOCK_ROLES` |
| `genres.ts` | ジャンル定数 `GENRES`（ID・ラベル・絵文字）と `genreLabel()`。ロビー・配役画面で共用 |
| `components/Toast.tsx` | 共通トーストコンポーネント（現在は部品のみ、Socket.io統合時に使用） |
| 各画面のハードコード | プレイヤー名（たろう・はなこ・けんじ）、準備状況、スコア等。配役画面は `MOCK_ROLES` / `FULL_SCRIPT` から導出 |

モックプレイヤーの割り当て：

| 条件 | myPlayer |
|------|---------|
| isHost | たろう |
| playerName === 'けんじ' | けんじ |
| その他ゲスト | はなこ |
