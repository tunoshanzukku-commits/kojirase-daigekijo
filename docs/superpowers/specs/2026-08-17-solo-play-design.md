# 1人プレイ対応 設計書

作成日: 2026-08-17

## 背景

これまで最小人数は2人だった。1人プレイの需要が見込めるため、1人でも遊べるようにする。

調査の結果、**進行ロジックは1人でもそのまま動く**ことが分かった。準備同期（`allReady`）・録音・アップロード収集（`uploadExpected`）・採点（`performers`）・ロビー復帰（`allReturned`）は、いずれも在室者の集合を数えるだけで人数を仮定していない。

問題は2つに絞られる。

1. **「2」がガードとして直書きされている**（サーバー・クライアント・台本検証の3箇所）
2. **既存9本の台本がすべて対話劇**で、1人で選ばれると会話の片側だけが残った台本になる

つまり本質はコンテンツ側であり、**ソロ用の台本を新規に書く**のが作業の本体になる。

## 決定事項

| # | 決定 | 理由 |
|---|------|------|
| 1 | ソロは「一人芸を演じきる本編」として扱う | 練習モードではなく、AIの講評と称号を受け取る体験を成立させる |
| 2 | 台本の形式は**「相手が見えない対話」に統一** | 電話・留守電・取調べなど。相手の返事を聞く「間」が自然に作れ、150秒を喋りっぱなしで埋めなくて済む。純粋な独白は間を自分で作る必要があり難度が高い |
| 3 | **まず1本（コメディ）書いて確かめてから残り7本** | 既存9本（対話劇）と書き味が違うため、8本一気に書くと形式が合わなかったときの手戻りが大きい |

## スコープ

**含む**
- 最小人数を1にするコード変更
- AI台本生成のソロ分岐
- ソロ台本の執筆規約とデータ仕様
- コメディのソロ台本1本
- 上記の自動テスト

**含まない（別スライス）**
- 残り7ジャンルのソロ台本（本スライスの検証後に着手）
- ソロ専用のUI演出（リアクション欄の出し分けなど）
- 演技時間の設定画面（既存の保留課題）

## コード変更点

### 定数の一元化

`shared/constants.ts` に `MIN_PLAYERS = 1` を新設する。現状は「2」がサーバーとクライアントに別々に直書きされており、片方だけ直すと食い違う。`MAX_PLAYERS` が既に同ファイルにあるので対称になる。

### 変更するファイル

| ファイル | 変更内容 |
|---|---|
| `shared/constants.ts` | `MIN_PLAYERS = 1` を追加 |
| `server/src/handlers.ts` | `room.players.size < 2` を `< MIN_PLAYERS` に。エラー文言も合わせる |
| `server/src/ai/scriptLibrary.ts` | `parsePlay` の `minPlayers < 2` を `< 1` に |
| `client/src/screens/LobbyScreen.tsx` | 開始ボタンの `disabled` 条件（2箇所）とラベル分岐から人数条件を外す |
| `prompts/script-user-solo.md`（新規） | 1人用のユーザープロンプト |
| `server/src/ai/scriptGen.ts` | 人数が1のとき solo テンプレートに切り替える |
| `client/src/screens/ResultScreen.tsx` | 参加者が1人のとき「みんなの結果を X でシェア」を出さない |
| `doc/仕様書.md` | プレイ人数の記述を「1〜10人（2〜8人推奨）」に |

`handlers.ts` のガードは `MIN_PLAYERS = 1` では実質到達しない（ホストが必ず1人いるため）。防御として残すが、プレイヤーに見えるのはクライアント側のラベルだけになる。

### 書き換える既存テスト

現仕様を固定しているテストが2件ある。削除ではなく**新仕様の検証に反転**させる。

| テスト | 変更後 |
|---|---|
| `handlers.game.test.ts` 「start_game は1人だと error でガードする」 | 1人で `start_game` が通り `script_ready` が届くことの検証に |
| `scriptLibrary.test.ts` 「parsePlay は minPlayers < 2 を弾く」 | `minPlayers: 0` を弾き、`minPlayers: 1` は受け入れることの検証に |

### AI生成のソロ分岐

`prompts/script-user.md` は「各プレイヤーに3〜4回ずつ台詞が回るようにする」と指示している。1人だと行数の下限（8〜12行）と矛盾し、かつ対話劇を書かせてしまう。

`scriptGen` は人数が1のとき `prompts/script-user-solo.md` を使う。システムプロンプトは共通のままとし、形式の指示はユーザープロンプト側に置く。solo テンプレートには次を含める。

- 相手が見えない対話であること（電話・留守電・取調べなど、相手の声は無い）
- 相手の台詞は書かず、受け答えだけで相手の発言が分かるようにすること
- `action` に「相手の返事を聞く」間を入れること
- 合計10〜12行、本文合計は360字以内（後述の尺の根拠）

## ソロ台本のデータ仕様

`minPlayers: 1, maxPlayers: 1` に固定する。

これだけで `selectPlay` の人数フィルタ（`playerCount >= p.minPlayers && playerCount <= p.maxPlayers`）が効き、**1人なら必ずソロ台本、2人以上なら絶対にソロ台本が選ばれない**という棲み分けが自動的に成立する。選択ロジックの変更は不要。

`parsePlay` は `roles.length >= maxPlayers` を要求するので、`roles` はちょうど1件。`entries` の `roleIndex` はすべて0になる。

## 「相手が見えない対話」の執筆規約

既存の対話劇とは別の縛りが要る。以下を守る。

1. **相手の台詞は書かない。** 受け答えだけで相手が何を言ったかが分かるように書く。
2. **`action` に間を明示する。**「相手の返事を聞く」「向こうが黙る」などを入れ、演者が黙る時間を正当化する。これが無いと演者は150秒を喋り続けようとして破綻する。
3. **最終行で反転させるか落とす。** 一人芝居は締まりが全てなので、最後の1行に山を置く。
4. **役は1つだけなので、既存の「役 k は役 0〜k しか参照できない」という縛りは適用されない。** 代わりに上の3点が縛りになる。

### 尺の基準

演技時間の上限は `RECORDING_LIMIT_SEC = 150秒`。既存台本で発生している尺超過を繰り返さないため、**書いた時点で必ず測る**。

測り方は既存の実測条件を再利用する（**4字/秒＋行間0.8秒/行**）。

ソロでは「相手の返事を聞く間」が体験の中心なので、**本文だけで150秒を使い切ってはいけない**。既存の測り方は通常の行間しか見ておらず、聞く間（1回あたり2〜3秒）は別に積む必要がある。

基準を次のように置く。

- **10〜12行、本文合計360字以内**
- 本文: 360 ÷ 4 = 90秒、行間: 12 × 0.8 = 9.6秒 → **約100秒**
- 聞く間: 6箇所 × 3秒 = 18秒
- **合計 約118秒**（150秒に対して30秒強の余裕）

余裕を残すのは、演技のテンポが人によって大きく変わるためと、上限に達すると録音がサーバー側で強制終了され最後の1行が失われるため。最終行に山を置く形式なので、ここが切れると台本が成立しない。

## 8ジャンルの企画

本スライスではコメディのみ実装し、残りは次スライスで書く。企画は先に決めておく。

| ジャンル | 状況 | 見えない相手 |
|---|---|---|
| コメディ | クレーム電話をかけたが、途中で自分の落ち度に気づく | サポート窓口 |
| ホラー | 誰もいないはずの実家からビデオ通話が来る | 「母」 |
| 恋愛 | 告白の練習を留守電に吹き込んでいたら本人に繋がっていた | 想い人 |
| 時代劇 | 御前に召し出され、姿の見えない殿に申し開きをする | 殿 |
| SF | 通信に8分の遅延がある探査機の相棒と交信する | 相棒 |
| ミステリー | 取調室で刑事の質問に答える | 刑事 |
| 感動 | 亡くなった人の携帯にかけ続けている | 出ない相手 |
| カオス | 役所の窓口で「呪い」の受理手続きをする | 職員 |

コメディを最初に書くのは、最もプレイされるジャンルでトーンの良し悪しを判断しやすいため。

## 検証

### 自動テスト（サーバー）

- 1人で `create_room` → `set_genre` → `start_game` が通り、`script_ready` の役が1件であること
- `parsePlay` が `minPlayers: 1` を受け入れ、`0` を弾くこと
- `selectPlay` が1人のときソロ台本を選び、2人以上のときソロ台本を除外すること
- 1人で録音終了から `evaluation_complete` まで到達すること（既存の収集・採点経路が人数1で壊れないことの回帰）

### 尺の測定

使い捨てスクリプトで測る（`server/` 直下に置かないと相対 import が解決しない）。`loadPlays(playsDir())` → `toScriptData(play, ['テスト'])` で `entries` を展開し、`line.length` の合計と行数から上の式で秒数を出す。

### 手動確認

ユーザーが実際に1人で通しプレイし、**尺と間の取りやすさ**を確認する。ここが本スライスの受け入れ条件。

## 既知の相互作用

**繰り越しバグ「切断中プレイヤーが人数と配役に混じる」との関係**: これまでは切断中のゴーストが2人の最小人数を満たしてしまう問題があったが、最小人数が1になることでこの経路は消える。配役にゴーストが混じる問題自体は残る（別課題）。

## リスク

- **形式が合わない可能性**: 「相手が見えない対話」が実際に演じてみると間延びする、あるいは逆に忙しい可能性がある。1本先行して確認する進め方はこのリスクへの対応。
- **AI生成のソロ台本は実キーでしか確認できない**: 自動テストはスタブモードで走るため、solo プロンプトの出力品質は手動確認になる。
