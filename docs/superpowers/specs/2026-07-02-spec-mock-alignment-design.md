# 仕様書・モック整合対応 設計書

*作成日：2026-07-02*

## 背景

フロントエンドモック（`client/`）と仕様書（`doc/`）の突き合わせ評価で、以下の3種類の課題が見つかった。

1. frontend仕様書がモックの実装に追いついていない（BGM/SFXパネル、GameContext拡張）
2. モック側の不整合（CastingScreenのハードコード、START!表示、ResultScreenの型）
3. どのドキュメントにもない設計の穴（エラーUI、切断UI、マイク許可、台本生成待ち）

本設計はこれらをバックエンド統合前にすべて解消する。

## 決定事項

| 論点 | 決定 |
|------|------|
| 台本生成待ちUI | ロビー画面内オーバーレイ（画面追加なし） |
| マイク許可の取得タイミング | 準備画面の表示時に取得。許可が準備完了の前提条件 |
| エラー表示 | 入室失敗＝フォーム直下インライン / ゲーム中の非同期エラー＝画面上部トースト |
| ホスト切断 | モーダル「ホストが退出したためルームが解散されました」→ OKでトップへ |
| ゲスト切断 | トースト「〇〇が退出しました」＋参加者一覧から削除。ゲームは続行 |
| 切断者の結果表示 | ランキング最下位にグレーの退出カード「🚪 途中退出のため評価なし」（星・コメント非表示） |

## A. frontend仕様書の更新（doc/frontend仕様書.md）

1. **4-5 録音画面**：BGM/SFXスライドパネルを追記
   - 画面右端の「音」タブで開閉するスライドパネル
   - BGM 4種（ドラマチック🎻 / 不気味👻 / コミカル🎵 / バトル⚔️）。単一選択・再タップまたは🔇で停止
   - 効果音 6種（ドラムロール🥁 / どーん💥 / ファンファーレ🎉 / 悲鳴😱 / 笑い声🤣 / チーン🔔）。タップで単発再生（押下時フラッシュ演出）
   - 誰でも操作可。backend仕様書の `send_bgm` / `send_sfx` / `bgm_changed` / `sfx_played` に対応
2. **2章 GameContext**：`script: ScriptData | null` と `scores: PlayerScore[]` を追記。Socket.io統合時にサーバーの RoomSnapshot を反映する受け皿である旨を明記
3. **4-2 ロビー**：台本生成中オーバーレイを追記
   - ホストが「ゲームを開始する」を押すと、ロビーの上に半透明オーバーレイ「✍️🤖 AIが台本を執筆中...」＋選択ジャンル名＋スピナーを全員に表示
   - `script_ready` 受信で配役画面へ遷移。エラー時はオーバーレイを閉じ、トーストでエラーを表示してロビーに戻る
4. **4-4 準備画面**：マイク許可フローを追記
   - 画面表示時に `navigator.mediaDevices.getUserMedia({ audio: true })` を実行
   - 状態：`pending`（確認中）/ `granted`（🎤 マイクOKバッジ）/ `denied`（案内カード＋再試行ボタン）
   - `denied` の間は準備完了ボタンを無効化。マイクOKが準備完了の前提条件
5. **新章「エラー表示」**
   - トップ画面の入室失敗（ルームが見つからない・ゲーム進行中）：フォーム直下に赤文字インライン表示
   - ゲーム中の非同期エラー（Claude API失敗等）：画面上部の共通トーストで通知（自動消滅、数秒）
6. **新章「切断時のUI」**：決定事項テーブルの内容（ホスト切断モーダル / ゲスト切断トースト / 結果画面の退出カード）
7. **4-5 カウントダウン**：「0になったらSTART!を約0.8秒表示してから録音フェーズへ移行」と明確化
8. **5章 モックデータ**：モック変更（GENRES共通化・MOCK_ROLES追加等）に合わせて更新

## B. モック修正（client/src/）

1. **CastingScreen**：ハードコードの `MY_ROLE` / `OTHER_ROLES` / `WORLD` 直書きを廃止
   - `getMockPlayer(ctx.isHost, ctx.playerName)` で自分のモックプレイヤーを決定
   - モックの `RoleInfo[]`（mockScript.tsに追加）から自分の役名・説明、他プレイヤーの役一覧を導出
   - 自分のセリフは `FULL_SCRIPT` から `player === myPlayer` で抽出
   - ジャンル表示は `ctx.genre` から解決。`GENRES` 定数を LobbyScreen から共通ファイル（`genres.ts`）へ移動し両画面で使用
2. **RecordingScreen**：カウントダウン0で「START!」を0.8秒表示してから録音フェーズへ移行
3. **ResultScreen**：独自の `PlayerResult` 型を廃止し、`types.ts` の `PlayerScore` 型（`playerName`）に統一
4. **LobbyScreen**：「ゲームを開始する」→ 生成オーバーレイを約2.5秒表示 → 配役画面へ（モック演出）
5. **PrepareScreen**：実際に `getUserMedia` でマイク許可を取得（モックでも本物の許可フロー）。許可状態バッジ・拒否時の案内カード・準備完了ボタンの無効化
6. **新規 `components/Toast.tsx`**：共通トーストコンポーネント（画面上部・自動消滅）。当面はモック内で使用箇所が少なくても部品として用意
7. **切断モーダル・退出カードのモック実装は見送り**：バックエンドなしではデモ不能なため仕様書のみ。Socket.io統合時に実装

## 対象外（今回やらないこと）

- Socket.io統合そのもの
- SNSシェア画像生成
- ハプニングイベント
- BGM/SFXの実音声再生（モックはUI演出のみ）

## テスト方針

モックのため自動テストは追加しない。修正後に `npm run build`（tsc + vite build）で型エラーがないことを確認し、開発サーバーでホスト/ゲスト両導線を目視確認する。
