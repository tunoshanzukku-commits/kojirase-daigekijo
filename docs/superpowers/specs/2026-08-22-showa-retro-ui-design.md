# ロビー以降の画面を昭和レトロにする 設計書

作成日: 2026-08-22

## 背景

トップ画面を「芝居小屋の表構え」に作り替えた（`f302277`）。わら半紙の地、墨と朱の二色、二重罫の枠、角丸の全廃。しかしロビー以降は手つかずで、入室した瞬間に水色パステルの現代UIへ戻る。

現状の令和要素の分布はこうなっている。

| 画面 | 行数 | rounded | sky | purple | bg-white | slate |
|---|---|---|---|---|---|---|
| RecordingScreen | 427 | 15 | 18 | 7 | 6 | 19 |
| LobbyScreen | 250 | 20 | 9 | 7 | 6 | 23 |
| PrepareScreen | 234 | 9 | 5 | 7 | 3 | 17 |
| ResultScreen | 198 | 11 | 8 | 3 | 4 | 21 |
| CastingScreen | 117 | 7 | 2 | 6 | 3 | 13 |
| EvaluatingScreen | 74 | 1 | 1 | 1 | 0 | 3 |
| ConfirmDialog / Toast | 88 | 4 | 2 | 0 | 2 | 8 |

**この分布そのものが問題の核心**である。色が各画面に直書きされているため、色を一つ変えるのに1,400行を触ることになる。今回の作業は見た目を変えるだけでなく、次に色を変えたくなったときの費用を下げる作業でもある。

## 決定事項

| # | 決定 | 理由 |
|---|------|------|
| 1 | **飾りの絵文字だけ外す。** リアクション（👏😂🔥😍💪）とBGM/SE（🎻👻🥁💥ほか）は残す | 前者は `shared/constants.ts` の `EMOJIS` で定義された仕様そのもの、後者は操作ラベル。見た目の都合で仕様を曲げない |
| 2 | **ジャンルは背景ではなく差し色で示す。** 地は全画面わら半紙で統一 | 昭和の印刷物は紙が地で、色は差し色。全面グラデは当時の印刷では刷れないので存在しない。ジャンルが一目で分かるという機能は帯・罫・検印の色で保つ |
| 3 | **トークンと共通クラスに集約してから各画面を載せ替える** | 各画面に直書きする方式（現状）がこの大工事を招いた。同じ借金を積み増さない |

## スコープ

**含む**
- デザイントークンの追加（`tailwind.config.js`）
- 共通クラスの新設（`index.css` の `@layer components`）
- `GENRE_BG` を `GENRE_ACCENT` に置き換え、CSS変数で全画面へ流す
- 6画面と共通部品2つの載せ替え
- 飾りの絵文字の置き換え

**含まない**
- 画面遷移・イベント契約・状態管理の変更（**一切触らない**）
- トップ画面（実装済み）
- 文言の変更（絵文字を外した箇所で語を補う場合を除く）
- スコアカード画像・OGP画像

## デザイントークン

`tailwind.config.js` の `theme.extend.colors` に追加する。墨・朱・生成りはトップ画面で導入済みなので、不足分だけ足す。

| 名前 | 値 | 用途 | 置き換え前 |
|---|---|---|---|
| `sumi` | `#241c17` | 本文・枠・主ボタン | `slate-900` / `slate-700` |
| `usuzumi` | `#6b5f52` | 補助文字・説明 | `slate-500` / `slate-400` |
| `shu` | `#b8352c` | 警告・強調・エラー | `red-500` / `purple-600` の一部 |
| `kinari` | `#f7f1e3` | パネルの地・反転文字 | `bg-white` / `bg-white/80` |
| `kei` | `#cdbfa4` | 罫線・区切り | `border-sky-100` / `border-sky-200` |
| `washi` | `#f0e7d2` | 画面の地（既存の `.bg-washi`） | `GENRE_BG` のグラデ |

**角丸は全廃する。** `rounded-*` は使わない。昭和の印刷物・看板に丸角はほぼ出てこない。例外は検印（真円）のみ。

**書体**は既存の `font-display`（Kaisei Decol）を見出しに使う。本文は端末のフォントのままとし、追加の読み込みはしない。

## ジャンル差し色

`GENRE_BG`（8つのグラデ文字列）を廃止し、`GENRE_ACCENT`（8つの色）に置き換える。色は昭和の色名から採り、彩度を落とす。

| ジャンル | 色名 | 値 |
|---|---|---|
| romance | 紅梅 | `#9d4448` |
| horror | 藍鉄 | `#2f4550` |
| comedy | 山吹 | `#8a6519` |
| jidai | 深緑 | `#46603f` |
| sf | 群青 | `#3a4f7a` |
| mystery | 葡萄鼠 | `#5f4c6b` |
| emotion | 錆浅葱 | `#3f6b67` |
| chaos | 朱 | `#b8352c` |

**8色とも、生成り（`#f7f1e3`）の文字を載せてコントラスト比 4.5:1 以上を確保できる明度に落としてある。** 差し色は帯の地として使い、その上に生成りの見出しが乗るため、明るい色は選べない。当初案の 紅梅 `#c1666b`・山吹 `#c9932f`・錆浅葱 `#5b8a86` はいずれも 2.5〜3.6:1 しかなく、見出しが読めなかったので暗く採り直した。**色を調整するときはこの下限を必ず確認すること。**

**流し方は CSS変数1本。** `App.tsx` のラッパーに `style={{ '--genre': GENRE_ACCENT[genre] ?? '#241c17' }}` を置く。各画面は `var(--genre)` を見るだけで、ジャンルを知る必要がない。ジャンル未選択（トップ・ロビー）では墨にフォールバックする。

この設計により、ジャンルの色を変えたいときに触るのは `genreStyles.ts` の1ファイルだけになる。

## 共通クラス

`index.css` の `@layer components` に置く。React部品にしないのは、props の設計が要らず、既存の Tailwind の書き味を保てるため。

| クラス | 中身 | 置き換え前 |
|---|---|---|
| `.washi-panel` | 生成り地、墨の細枠、角なし、影なし | `bg-white/80 backdrop-blur rounded-2xl shadow-sm border border-sky-100` |
| `.washi-band` | 見出しの帯。地は `var(--genre)`、文字は生成り、字間広め | `<h2 className="font-bold text-xl text-slate-900">` |
| `.btn-sumi` | 墨ベタ・生成り文字・角なし。主操作 | `bg-purple-600 text-white rounded-2xl` |
| `.btn-outline` | 透明地・墨の枠2px。副操作 | `bg-white border border-sky-200 rounded-2xl` |
| `.btn-shu` | 朱ベタ。破壊的操作（解散・中断・キック） | `text-red-400` 系 |
| `.field` | 生成り地・墨の枠・角なし・朱のフォーカスリング | `bg-sky-50 rounded-xl focus:ring-purple-400` |
| `.rule` | 墨の細い横罫。区切り | `border-t border-sky-100` |
| `.seal` | 検印。真円・朱の枠・朱文字・わずかに傾ける | （新規） |

`disabled` の見え方は各ボタンクラスに含める（`disabled:opacity-30`）。現状は画面ごとに `disabled:opacity-40` と `disabled:opacity-50` が混在しているので、この機会に揃える。

## 画面ごとの適用

原則は機械的な置換で、判断が要るのは飾りの絵文字と見出しの扱いだけ。

- **App.tsx** — `bg` の算出を `bg-washi` 固定にし、`--genre` を設定する。トップだけ特別扱いしていた分岐は不要になる。
- **LobbyScreen** — ルームコードの表示を「番付表の演目札」の見立てにする。参加者一覧は罫線で区切る。ジャンル選択ボタンは選択中だけ差し色ベタ、他は枠のみ。
- **CastingScreen** — 役名は `.washi-band`。他プレイヤーの役は罫線区切りの一覧に。
- **PrepareScreen** — 準備完了の状態表示を検印（押した人に朱の丸）で示す。
- **RecordingScreen** — 最大の画面。**リアクションとBGM/SEのボタンは絵文字を残したまま枠と色だけ差し替える。** 声量メーターは朱のベタ塗り、RECタイマーは墨地に生成り文字。
- **EvaluatingScreen** — 演出は維持し、色だけ差し替える。
- **ResultScreen** — 順位を `🥇🥈🥉` から **「第一席」「第二席」…** に置き換える。「席」は落語や講談の演目を数える語で、「大劇場」「大根役者選手権」の見立てに合う。現状は `MEDALS[rank] ?? '🎭'` で4位以降が絵文字にフォールバックしているが、**漢数字一〜十の対応表を持たせて `MAX_PLAYERS`（10人）まで欠けなく出す**。称号バッジは朱地・生成り抜き。
- **ConfirmDialog / Toast** — 全画面に出るので最優先で揃える。角丸を外し、`.washi-panel` を使う。

## 絵文字の扱い

| 絵文字 | 所在 | 扱い |
|---|---|---|
| 👏😂🔥😍💪 | RecordingScreen | **残す**（`EMOJIS` 定数＝仕様） |
| 🎻👻🎵⚔️🥁💥🎉😱🤣🔔 | RecordingScreen | **残す**（BGM/SEの操作ラベル） |
| ★ | ResultScreen | **残す**（5段階評価の表示。昭和の印刷物にも存在する記号） |
| 🥇🥈🥉 | ResultScreen | **番付表現に置換**（壱席・弐席・参席） |
| 🎭 | Casting / Prepare / Result | **外す**（見出しの帯に置換） |
| 🏆 | ResultScreen | **外す**（「最優秀俳優賞」の帯に置換） |
| 🚪 | ResultScreen | **外す**（「退出しました」の文言が既にある） |
| 🎧 | Prepare / Result | **外す**（「自分の演技を聞く」の文言が既にある） |
| 🎬🎤 | Prepare / Recording | **外す**（文言が既にある） |
| ⚠️ | Casting / Prepare / Recording | **外す**（`.btn-shu` の朱で危険は伝わる） |
| 🔗 | ResultScreen | **外す**（「共有」の文言が既にある） |
| 🏅 | ResultScreen | **外す**（称号バッジ自体が朱地の帯になる） |

外す絵文字はいずれも**隣に同じ意味の文言が既にある**ため、情報は失われない。

## 検証

クライアントにコンポーネントテストは無く、この変更でテストは増やさない（`className` を変えるだけの作業に対してテスト基盤を導入するのは釣り合わない）。代わりに次の3点で担保する。

1. **`npm run build`（`tsc && vite build`）が通ること。** 型と JSX の構文はここで捕まる。
2. **既存の `npm test`（xShare の6件）が通ること。** ロジックに触れていないことの間接的な確認。
3. **6画面と共通部品2つの diff が `className` と装飾JSXだけに収まっていること。** これが本命の合格条件。純粋な見た目替えなので、**ロジック行（イベントハンドラ・状態・条件分岐・API呼び出し）が1行でも変わっていたら差し戻す**。自動テストが無い代わりに、diff の性質そのものを合格条件にする。

この規則の対象は `screens/*.tsx` と `components/{ConfirmDialog,Toast}.tsx` の8ファイル。次の3つは定義そのものを足す作業なので対象外とする。

- `tailwind.config.js` — トークンの追加
- `index.css` — 共通クラスの新設
- `genreStyles.ts` と `App.tsx` — `GENRE_BG` → `GENRE_ACCENT` の置き換えと CSS変数の設定

ただし `ResultScreen` の順位表示だけは、絵文字から漢数字への置換に対応表の追加を伴う。これは装飾のための追加であり、ロジックの変更ではない（順位の算出そのものは無改造）。

**手動確認**はユーザーが実機で全画面を通しプレイして行う。受け入れ条件は「ロビー以降が昭和で通っていること」と「操作が壊れていないこと」の2点。

## リスク

- **RecordingScreen が427行と突出している。** 声量メーター・タイマー・リアクション・BGM/SEが1ファイルに同居しており、置換の量が多い。単独タスクに分け、他の画面が終わってから着手する。
- **「差し色」の効き方は実機で見ないと分からない。** 8ジャンルすべてを机上で判断するのは無理があるので、実装後にユーザーが数ジャンル触って調整する前提で進める。色は `genreStyles.ts` の1箇所なので調整は安い。
- **絵文字を外すと余白の重心が変わる。** 🎭 は72pxの塊なので、外した箇所は間延びしやすい。帯や罫で埋める前提で置換する。
