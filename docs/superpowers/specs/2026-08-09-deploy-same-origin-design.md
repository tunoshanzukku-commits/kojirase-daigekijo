- 日付: 2026-08-09

- ブランチ: `feature/deploy-same-origin`
- 関連: [全体仕様書](../../../doc/仕様書.md) §7（ホスティング＝Railway 想定）

## 1. 背景とスコープ

これまで検証は `localhost` の2タブだけで行ってきた。**LAN の実機（スマホ）では `getUserMedia` がセキュアコンテキストを要求するため録音が動かない**。Web Share API も同じ制約を持つ。つまり HTTPS 化は「公開のための作業」である以前に、**このゲームの中心機能を実機で初めて検証できるようにする作業**である。

本スライス（A）は**デプロイ基盤だけ**を扱う。公開ガードと台本ライブラリは別スライスに分ける。

### 決定事項（ブレインストーミングで確定）

- **1サービス同居**：Express がビルド済み `client/dist` を配信し、同じドメインで Socket.IO も受ける。分離構成（CDN＋API）は見送り。
  - 理由は速度ではなく**設定ミスが起きうる面の数**。同一オリジンなら CORS・サーバーURL埋め込み・混在コンテンツという3大ハマりどころが**構造的に消える**。バンドルは gzip 78KB と軽く、CDN との体感差は小さい。
  - 分離の唯一の実質的利点「クライアント更新でサーバーを止めない」は、デプロイ頻度の低い個人運営では滅多に効かない。
- **Vercel/Netlify のサーバーレスにサーバーは載せられない**（確認済みの構造的制約）:
  1. サーバーレス関数はリクエストごとに使い捨てで、全員のソケットを抱え続けられない
  2. `io.to(roomCode).emit(...)`（他プレイヤーへの push）ができない
  3. `roomStore` の Map が関数インスタンスごとに分裂する
  4. リクエストボディのサイズ上限により `POST /upload` が通らない
  Vercel を使うなら「クライアントのみ」＝分離構成に戻る。今回は採らない。
- **ホスティング先は Railway を第一候補**（仕様書§7・常時稼働・HTTPS付きサブドメイン自動）。ただし本設計のプラットフォーム依存は **`PORT` とビルド/起動コマンドだけ**に閉じ込めるので、Render・Fly へも同構成で移せる。
- **公開範囲は「誰でも使える形」**を目指すが、**URLを広く配るのはスライスB（公開ガード）完了後**とする。本スライス完了時点では URL を配らずに実機確認する。

### 非スコープ

- レート制限・日次ゲーム数上限・キルスイッチ（`PUBLIC_ENABLED` / `AI_ENABLED`）→ **スライスB**
- 手書き台本ライブラリ（上限到達時のフォールバック内容）→ **スライスC**
- 独自ドメイン、CDN、複数インスタンス、ルームの永続化

## 2. アーキテクチャ

Express が1プロセスで3役を担う。**ルーティングの順序が仕様の一部**である。

```
1. GET  /health          ヘルスチェック（既存）
2. POST /upload          音声アップロード（既存）
3.      /socket.io/*     WebSocket（既存・Socket.IO が内部で処理）
4. GET  /assets/* ほか    client/dist の静的ファイル（新規）
5. GET  *                index.html を返す（SPA フォールバック・新規）
```

**5 は必ず最後**に登録する。先に置くと `/upload` や `/socket.io` が index.html に飲まれ、ゲームが起動しない。

静的配信と SPA フォールバックは **`NODE_ENV === 'production'` のときだけ**有効にする。開発時は Vite の dev サーバーが 5173 でクライアントを配信するため不要で、テスト（`buildServer()` を使う統合テスト）にも影響を与えない。

## 3. 同一オリジン化

### 3.1 クライアントのサーバーURL

`client/src/config.ts` の `SERVER_URL` は現在 `VITE_SERVER_URL ?? 'http://localhost:3001'`。本番では**同一オリジン**を指すようにする。

- `VITE_SERVER_URL` が明示されていればそれを使う（将来分離構成に戻す逃げ道として残す）
- 開発時（`import.meta.env.DEV`）は従来どおり `http://localhost:3001`
- 本番は `window.location.origin`

これにより、**本番URLをビルド時に埋め込む必要がなくなり**、環境変数の設定漏れで「本番だけ動かない」事故が原理的に起きなくなる。

### 3.2 CORS

現在 `app.use(cors())` と `io({ cors: { origin: '*' } })` が無条件で入っている。同一オリジンでは CORS は不要で、**公開サーバーに `origin: '*'` を残すべきではない**。

`NODE_ENV !== 'production'` のときだけ CORS を有効にする。開発時はクライアント 5173・サーバー 3001 で別オリジンになるため必要、本番では CORS ヘッダを一切出さない。

## 4. ビルドと起動

### 4.1 ルート `package.json` の新設

リポジトリ直下に `package.json` が無く、`client/` と `server/` が独立している。この状態ではホスティングサービスが「何をビルドして何を起動するか」を判断できない。ルートに追加する。

- `build`: server と client の依存を `npm ci`（両方に `package-lock.json` あり）で入れ、`client` をビルドする。**`dist/` は gitignore 済みなのでホスト側で生成する必要がある**
- `start`: server を起動する。`PORT` はプラットフォームが渡す環境変数を使う（`server/src/index.ts` で実装済み）
- `engines`: Node 20 以上を明示（`fetch` / `FormData` を標準として使っているため）

**ルート `package.json` 自身は依存を持たない**（scripts と engines だけ）。ホスティングサービスがルートで `npm install` を実行しても何も起きず、実際の依存インストールは `build` スクリプトが `client/` と `server/` それぞれに対して行う。

npm workspaces への移行は行わない。既存の `npm --prefix` 運用と tsconfig の paths を壊すリスクに対して得るものが小さい。

### 4.2 `tsx` を dependencies へ

`server/package.json` の `start` は `tsx src/index.ts` だが、**`tsx` は現在 `devDependencies` にある**。本番インストールで devDependencies を省くプラットフォームでは起動に失敗する。`dependencies` へ移す。

（TypeScript を事前コンパイルして純 JS で起動する案もあるが、`@shared/*` のパス解決とビルド構成が増えるため採らない。`tsx` 実行は既存の開発・テスト運用と同じで、追加の破綻要因が無い。）

### 4.3 環境変数

| 変数 | 用途 | 未設定時 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 台本生成・採点 | スタブ動作（実装済み） |
| `GROQ_API_KEY` | 文字起こし | スタブ動作（実装済み） |
| `PORT` | 待ち受けポート | 3001 |
| `NODE_ENV` | `production` で静的配信ON・CORS OFF | 開発扱い |

`.env` は gitignore 済みで、キーがリポジトリに入る心配はない。キーはプラットフォームの環境変数として設定する。

## 5. 運用上の制約（設計として明記する）

- **必ず1インスタンス。** ルーム状態はプロセスのメモリ上にあるため、複数レプリカにすると「部屋が見つからない」「片方のプレイヤーにだけイベントが届かない」が発生する。オートスケールは明示的に無効化する。
- **再デプロイ・再起動で進行中のルームは全消滅する。** 誰も遊んでいない時間に更新する。
- **HTTPS はプラットフォームのサブドメインで自動取得**され、証明書の作業は不要。
- スリープするプランを選んだ場合、最初のアクセスで数十秒待たされる（Render 無料プラン等）。Railway など常時稼働なら発生しない。

## 6. 検証

- ローカル: `NODE_ENV=production` で server を起動し、**クライアントを別途起動せずに** `http://localhost:3001` だけでゲームが表示・進行できること（同居配信とフォールバック順序の確認）。既存のサーバーテスト 162 件が引き続き通ること。
- デプロイ後、**スマホ実機**で:
  1. **マイク録音が動く**（HTTPS化の主目的。localhost 以外では HTTPS 必須）
  2. 2端末でルーム作成・参加・進行が同期する
  3. 結果画面の「音声を共有」が OS の共有シートに出る（Web Share もセキュアコンテキスト必須）
  4. `/health` が 200 を返す
- 音源ファイルは未配置のままでよい（欠損は無音で継続する設計・実装済み）。

## 7. 変更ファイル一覧（見込み）

- `package.json` — 新規（ルート。build / start / engines）
- `server/package.json` — `tsx` を dependencies へ
- `server/src/server.ts` — 本番のみ静的配信＋SPAフォールバック、CORS を開発時のみに
- `client/src/config.ts` — 本番は同一オリジンを指す
- `.env.example` — `NODE_ENV` の記載を追記（デプロイ時に設定する変数の一覧として）
